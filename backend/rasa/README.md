# Rasa NLU – OBE Chatbot Intent Detection

This directory contains the [Rasa](https://rasa.com/) NLU project used for
intent classification in the OBE (Outcome-Based Education) chatbot.

---

## Supported Intents

| Intent | Example Utterances |
|---|---|
| `generate_co` | "Generate course outcomes", "Create COs from syllabus" |
| `map_co_po` | "Map COs to POs", "Perform CO-PO mapping" |
| `calculate_attainment` | "Calculate attainment", "Compute CO attainment" |
| `detect_bloom` | "Detect Bloom level", "Classify this question's taxonomy" |
| `generate_report` | "Generate PDF report", "Download attainment report" |
| `student_marks` | "Upload student marks", "Enter exam scores" |
| `add_questions` | "Add questions to exam", "Configure exam questions" |
| `list_courses` | "List all courses", "Show my courses" |
| `help` | "Help", "What can you do" |
| `greet` | "Hello", "Hi" |
| `goodbye` | "Bye", "Goodbye" |

```

├── domain.yml       # Intents, slots, responses

│   ├── stories.yml  # Conversation flows
│   └── rules.yml    # Fixed rules (greet, goodbye, help, fallback)
```

## Quick Start

### 1. Install Rasa

Activate the project venv first, then:

```bash
pip install "rasa>=3.6.0,<4.0.0"
```

> Rasa requires Python 3.8–3.10. This project uses Python 3.10.

### 2. Train the Model

From the `backend/` directory:

```bash
python scripts/train_rasa.py
```

Or directly from this directory:

```bash
rasa train
```

Trained models are saved to `backend/rasa/models/`.

### 3. Start the Rasa Server

```bash
python scripts/start_rasa.py
```

Or directly:

```bash
cd backend/rasa
rasa run --enable-api --cors "*" --port 5005
```

The server listens on `http://localhost:5005` by default.  
Override with the `RASA_PORT` environment variable.

### 4. Configure the Backend

Set the `RASA_URL` environment variable to point to the Rasa server:

```bash
export RASA_URL=http://localhost:5005
```

If `RASA_URL` is not set, it defaults to `http://localhost:5005`.

If the Rasa server is **not running**, the backend automatically falls back to
keyword-based intent detection — so the chatbot continues to work without Rasa.

## Integration Architecture

```
User Message
     │
     ▼
ChatbotService.process_message()
     │
     ▼
RasaNLUClient.parse()   ◄─── POST /model/parse (Rasa server)
     │                          (falls back to keyword matching
     │                           if Rasa is not reachable)
     ▼
intent + entities + confidence
     │
     ▼
_dispatch() → domain handler → reply + data
```

The `nlu_source` field in the chatbot response indicates whether Rasa (`"rasa"`)
or keyword matching (`"keyword"`) was used.

## Testing the Rasa Server Directly

```bash
curl -X POST http://localhost:5005/model/parse \
  -H "Content-Type: application/json" \
  -d '{"text": "generate course outcomes from the syllabus"}'
```

Expected response:
```json
{
  "text": "generate course outcomes from the syllabus",
  "intent": {"name": "generate_co", "confidence": 0.98},
  "entities": [],
  "intent_ranking": [...]
}
```

## Adding New Intents

1. Add the intent name to `domain.yml` under `intents:` and add a response under `responses:`.
2. Add training examples to `data/nlu.yml`.
3. Add a story to `data/stories.yml` (optional).
4. Add a rule to `data/rules.yml` (optional).
5. Retrain: `python scripts/train_rasa.py`.
6. Add a handler in `backend/app/services/chatbot_service.py` under `_dispatch()`.
